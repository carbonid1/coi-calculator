## Findings considered and rejected

- **Solver loops silently stop at their iteration caps** (`factory-total.ts:264`,
  `:1070`, `:1109`; `calculate-linked-modules.ts:559`): true by reading, but
  when instrumented and run against the recorded-factory smoke scenarios every
  dispatch, contract, payment and link loop settled before its cap. Not worth
  a result-shape change until a save that fails to settle turns up; if one
  does, start from that save as a regression fixture.
- **Line-order cache "never hits"** (`calculate.ts:257-281`): it can hit within
  one solve; cheap and harmless.
- **`app/db` importing from `app/helpers`**: mostly type-only imports and leaf
  utilities; no runtime cycle found.
- **Exact `===` float comparison in `ratiosAreIdentical`** (`factory-total.ts:686-694`):
  intentional; it only decides whether to skip a re-solve.
- **Polling races, ETag handling, mod threading, JSON string escaping**: checked
  and sound (requests are serialised; mod routes run on the simulation thread).
- **Pinning `next` / `typescript` exactly**: the lockfile already protects installs.
- **Lockfile not part of the calculation cache version**: the solver has no
  runtime dependencies that affect results.
- **Direction ideas needing new UI** (an "apply to game" button, export/import
  of presets): rejected by the maintainer's no-new-UI rule. The same goals fit
  skills that drive the game's command API, as `rebalance-farms` already does.
